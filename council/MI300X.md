# The council on the MI300X

The guide for the council's eval on the MI300X: the calibration, the freezing of the pre-registration and the test, only once.
The rules are in [PREREGISTRATION.md](PREREGISTRATION.md); here there is only how it is done.

| Step | Where | Time |
|---|---|---|
| 0. Steps 3 and 4 of G1 | MI300X | 25 minutes |
| 1. Code and demo set | Mac → MI300X | 5 minutes |
| 2. The quick trial | MI300X | 15 minutes, plus the model if it is not there |
| 3. The calibration | MI300X | to be measured: about 45 reviews |
| 4. The freezing | Mac | 15 minutes |
| 5. The test | MI300X | to be measured: a few hours |
| 6. What to send | MI300X → Mac | 5 minutes |

The council and G1 use the same GPU: one run at a time, because the measured times count.

## 0. First: steps 3 and 4 of G1

The council runs in G1's engine container, with the same ROCm torch. So first you do steps 3 and 4 of `g1/README.md`:

- **step 3:** the `engine` container, from `vllm/vllm-openai-rocm:v0.30.0`;
- **step 4:** the fp32 against bf16 comparison. On ROCm the attention masks have had bugs: they would break the council too, without errors. If the answers diverge on more than 1 problem in 5, stop and note it in the run report: the council does not start.

## 1. Code and demo set, from the Mac

The eval writes the commit of the code and that of the pre-registration, so the machine needs the repo with `.git`. Copy it from a fresh clone of `main`, which has the council, the eval and G1 together:

```bash
# on the Mac
git clone -q https://github.com/AIVolve-Team/the-silent-council.git ~/hackathon/eval-mi300x
rsync -a --exclude .venv --exclude 'results*' ~/hackathon/eval-mi300x/ root@<IP>:~/hackathon/eval/
# the demo set is private: it goes only on this machine, never on GitHub
rsync -a ~/hackathon/the-silent-council/council/data/demo-set/ root@<IP>:~/hackathon/eval/council/data/demo-set/
```

In the container `~/hackathon` is seen as `/work`, so the repo is in `/work/eval`.

## 2. The quick trial

```bash
docker exec -it engine bash
cd /work/eval
command -v git >/dev/null || (apt-get update -q && apt-get install -y -q git)   # the eval needs git
SYSTEM_TORCH=1 NO_REALIGN=1 ./council/trial.sh --quick
```

- `SYSTEM_TORCH=1` uses the image's torch, the same as in step 4 of G1, instead of installing another one.
- The trial runs the tests without a model, downloads and checks the data, verifies the demo set and does one telepathy run on the 4 Italian contracts.
- It must end with the line `Done.` and say `GPU: cuda` and `Model weights in bfloat16`. If it stops, report the last lines of `council/results-trial/trial.log`, without fixing anything.

## 3. The calibration

```bash
docker exec -d engine bash -c "cd /work/eval && ./council/mi300x.sh calibration"
tail -f ~/hackathon/eval/council/results-mi300x/calibration/run.log      # from the host, to follow it
```

- Telepathy with 0, 10, 20 and 40 steps, and text, on CUAD dev and on the demo set. The W_a realignment is off: `mi300x.sh` turns it off by itself.
- It has finished when `Done. Tables for the calibration` appears in the log.
- It produces `calibration.md`, with aggregate numbers only, and the `.jsonl` files. The CUAD ones are public; those of the demo set contain sentences of the contracts and stay private.

## 4. The freezing, on the Mac

Send `calibration.md` and the `.jsonl` files (step 6 says how). On a new branch from `main`:

- the **steps**, with the pre-registration's rule: the highest F1 among 0, 10, 20 and 40 wins and, within 1 point, the value with fewer steps;
- the **confidence thresholds** proposed by the calibration;
- the section **Calibration on the MI300X**, with the pair-by-pair agreement with the Mac runs on the same code. If the yes/no answers diverge a lot, stop before the test;
- the line `Status: frozen on DD/MM/YYYY`, the commit, the PR and the merge into `main`.

Before the freezing someone on the team rereads the operational definitions, as the pre-registration asks.
Then copy the repo onto the machine again, with the same `rsync` as in step 1, after a `git pull` in the clone `~/hackathon/eval-mi300x`.

## 5. The test, only once

```bash
docker exec -d engine bash -c "cd /work/eval && STEPS=<fixed steps> ./council/mi300x.sh test"
tail -f ~/hackathon/eval/council/results-mi300x/test/run.log
```

- It starts only if the pre-registration is frozen and committed and the code has no local changes.
- It runs **only once**: a second run is a deviation, needs `--deviation` with the reason and must be written in the pre-registration.
- With 0 steps the tests on the thoughts are not run, as the pre-registration says: the log says so too.
- It has finished when `Done. Report in` appears in the log.

## 6. What to send

```bash
# on the Mac
rsync -a root@<IP>:~/hackathon/eval/council/results-mi300x/ ~/hackathon/results-mi300x/
```

- `report.md`, `numbers.json` and the charts: aggregate numbers only, they can be published.
- The `.jsonl` files: those of CUAD, ContractNLI and CLAUDETTE are public; those of the demo set and the `blind/` folder stay private and go only to whoever asks for them.
- At the end the machine is destroyed: it is paid for even when switched off.
