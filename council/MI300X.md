# Il Consiglio sulla MI300X

La guida per l'eval del Consiglio sulla MI300X: la taratura, il congelamento della pre-registrazione e il test, una volta sola.
Le regole sono in [PREREGISTRATION.md](PREREGISTRATION.md); qui c'è solo come si fa.

| Passo | Dove | Tempo |
|---|---|---|
| 0. I passi 3 e 4 di G1 | MI300X | 25 minuti |
| 1. Codice e set dimostrativo | Mac → MI300X | 5 minuti |
| 2. La prova veloce | MI300X | 15 minuti, più il modello se non c'è |
| 3. La taratura | MI300X | da misurare: circa 45 revisioni |
| 4. Il congelamento | Mac, con Claude Code | 15 minuti |
| 5. Il test | MI300X | da misurare: alcune ore |
| 6. Cosa mandare | MI300X → Mac | 5 minuti |

Il Consiglio e G1 usano la stessa GPU: un giro alla volta, perché i tempi misurati contano.

## 0. Prima: i passi 3 e 4 di G1

Il Consiglio gira nel container del motore di G1, con lo stesso torch ROCm. Per questo, prima, si fanno i passi 3 e 4 di `g1/README.md`:

- **passo 3:** il container `motore`, da `vllm/vllm-openai-rocm:v0.30.0`;
- **passo 4:** il confronto fp32 contro bf16. Su ROCm le maschere dell'attenzione hanno avuto bug: sbaglierebbero anche il Consiglio, senza errori. Se le risposte divergono su più di 1 problema su 5, ci si ferma e lo si scrive: il Consiglio non parte.

## 1. Codice e set dimostrativo, dal Mac

L'esame scrive il commit del codice e quello della pre-registrazione, quindi sulla macchina serve il repo con `.git`. Si copia da un clone nuovo di `main`, che ha insieme il Consiglio, l'eval e G1:

```bash
# sul Mac
git clone -q https://github.com/AIVolve-Team/the-silent-council.git ~/hackathon/eval-mi300x
rsync -a --exclude.venv --exclude 'risultati*' ~/hackathon/eval-mi300x/ root@<IP>:~/hackathon/eval/
# il set dimostrativo è privato: va solo su questa macchina, mai su GitHub
rsync -a ~/hackathon/the-silent-council/consiglio/dati/set-dimostrativo/ root@<IP>:~/hackathon/eval/consiglio/dati/set-dimostrativo/
```

Nel container `~/hackathon` si vede come `/work`, quindi il repo è in `/work/eval`.

## 2. La prova veloce

```bash
docker exec -it motore bash
cd /work/eval
command -v git >/dev/null || (apt-get update -q && apt-get install -y -q git) # all'esame serve git
TORCH_DI_SISTEMA=1 SENZA_RIALLINEAMENTO=1./consiglio/prova.sh --veloce
```

- `TORCH_DI_SISTEMA=1` usa il torch dell'immagine, lo stesso del passo 4 di G1, invece di installarne un altro.
- La prova fa i test senza modello, scarica e controlla i dati, verifica il set dimostrativo e fa una telepatia sui 4 contratti italiani.
- Deve finire con la riga `Fatto.` e dire `GPU: cuda` e `Pesi del modello in bfloat16`. Se si ferma, si riportano le ultime righe di `consiglio/risultati-prova/prova.log`, senza correggere niente.

## 3. La taratura

```bash
docker exec -d motore bash -c "cd /work/eval &&./consiglio/mi300x.sh taratura"
tail -f ~/hackathon/eval/consiglio/risultati-mi300x/taratura/giro.log # dall'host, per seguirla
```

- Telepatia con 0, 10, 20 e 40 passi, e testo, su CUAD di sviluppo e sul set dimostrativo. Il riallineamento W_a è spento: lo spegne `mi300x.sh` da sé.
- È finita quando nel log compare `Fatto. Tabelle per `.
- Ne escono `taratura.md`, con solo numeri aggregati, e i `.jsonl`. Quelli di CUAD sono pubblici; quelli del set dimostrativo contengono frasi dei contratti e restano privati.

## 4. Il congelamento, sul Mac

Si mandano `taratura.md` e i `.jsonl` (il passo 6 dice come). Con Claude Code, su un ramo nuovo da `main`:

- i **passi** con la regola della pre-registrazione: vince l'F1 più alto fra 0, 10, 20 e 40 e, sotto 1 punto, il valore con meno passi;
- le **soglie di confidenza** proposte dalla taratura;
- la sezione **Taratura sulla MI300X**, con l'accordo coppia per coppia con i giri del Mac sullo stesso codice. Se i sì/no divergono molto, ci si ferma prima del test;
- la riga `Stato: congelata il GG/MM/AAAA`, il commit, la PR e l'unione in `main`.

Prima del congelamento qualcuno del team rilegge le definizioni operative, come chiede la pre-registrazione.
Poi si ricopia il repo sulla macchina, con lo stesso `rsync` del passo 1, dopo un `git pull` nel clone `~/hackathon/eval-mi300x`.

## 5. Il test, una volta sola

```bash
docker exec -d motore bash -c "cd /work/eval && PASSI=<passi fissati>./consiglio/mi300x.sh test"
tail -f ~/hackathon/eval/consiglio/risultati-mi300x/test/giro.log
```

- Parte solo se la pre-registrazione è congelata e committata e il codice non ha modifiche locali.
- Gira **una volta sola**: un secondo giro è una deviazione, chiede `--deviazione` con il motivo e va scritto nella pre-registrazione.
- Con 0 passi le prove sui pensieri non si fanno, come dice la pre-registrazione: lo scrive anche il log.
- È finito quando nel log compare `Fatto. Rapporto in`.

## 6. Cosa mandare

```bash
# sul Mac
rsync -a root@<IP>:~/hackathon/eval/consiglio/risultati-mi300x/ ~/hackathon/risultati-mi300x/
```

- `rapporto.md`, `numeri.json` e i grafici: solo numeri aggregati, vanno.
- I `.jsonl`: quelli di CUAD, ContractNLI e CLAUDETTE sono pubblici; quelli del set dimostrativo e la cartella `cieca/` restano privati e vanno solo a chi li chiede.
- Alla fine la macchina si distrugge: anche spenta si paga.
